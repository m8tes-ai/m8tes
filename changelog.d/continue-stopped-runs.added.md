- `client.runs.continue_stopped(run_ids=None)` resumes the runs a plan limit stopped, paced by the plans that are open. It returns a `ContinueStoppedRuns` with the run ids that `started`, the ones left `waiting` (untouched, queued start and tries intact), the `skipped` ones (each with a stable `reason`: every run you named in `run_ids` that cannot be continued and, without `run_ids`, a stopped run whose start was refused or that changed while the call worked), `plans_connected`, `plans_open` and `next_plan_opens_at`, which is set only when every connected plan is closed and nothing was started. A run whose work was already started again as a new run (`retried_by_run_id` is set) is left out, because the retry is the run to continue. Omit `run_ids` for every stopped run of the account; pass up to 200 ids to be told why a run was left alone.
